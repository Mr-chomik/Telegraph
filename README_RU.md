# Fun — AI-газета из Telegram-каналов

**Читать на [English](README.md)**

Fun — это самохостинговое веб-приложение, которое автоматически собирает из
Telegram-каналов настоящую цифровую газету. Оно забирает сырые посты,
дедуплицирует и кластеризует их в истории, пишет тексты, вёрстает газету
(первая полоса, рубрики, «Лёгкое чтение») и отдаёт её как веб-приложение в
аутентичной печатной эстетике.

Редакционный пайплайн работает **без ИИ** (детерминированные запасные
варианты) и опционально дорабатывается локальной LLM (Ollama). Каждая статья
прослеживается вплоть до исходного поста в Telegram.

## Архитектура

```
Telegram ──► apps/worker ──► packages/core ──► Postgres ──► apps/web
              (cron jobs)      (чистая логика)  (Prisma 7)   (Next.js 16)
```

- **`packages/core`** — общая детерминированная редакционная логика:
  нормализация, фильтр спама, кластеризация (косинус 0.55), классификация,
  оценка важности, написание/форматирование текстов и **движок вёрстки**
  выпусков. Полностью покрыта юнит-тестами, без IO.
- **`packages/db`** — Prisma-схема, сгенерированный клиент и демо-сид.
- **`apps/worker`** — node-cron планировщик идемпотентных job'ов: `fetch`
  (загрузка из Telegram), `process` (пайплайн), `generateEdition` (вёрстка),
  `cleanup` (ретенция).
- **`apps/web`** — Next.js App Router: авторизация, главная, просмотр газеты
  (переворот страницы, оглавление, модалка статьи с источниками), архив,
  поиск, настройки, «Моя газета», админ-панель.

### Драйверы загрузки из Telegram

Два взаимозаменяемых драйвера, выбираются переменной `TELEGRAM_DRIVER`:

- **`public` (по умолчанию, без логина):** читает публичную страницу
  `t.me/s/<user>` — текст, округлённые просмотры, фото. Работает для любого
  публичного канала без единого ключа; достаточно для демо. Время поста
  берётся из видимого элемента `<time datetime>` (токен `data-view` — это
  время рендера страницы, для дат он не годится).
- **`mtproto` (полная точность):** GramJS с вашим аккаунтом. Требует
  `TELEGRAM_API_ID`/`TELEGRAM_API_HASH` (с https://my.telegram.org/apps) и
  однократный `npm run tg:login` (телефон + код), который сохраняет сессию в
  `data/tg.session`. Точные просмотры, пересылки, больше постов за запуск.

`fetch` повторяет попытки для каналов в статусе `ERROR`, поэтому кратковременный
сбой сети не отключает канал навсегда. Так как соединение с t.me нестабильно
всплесками (DNS/TCP-обрывы, исчезающие за секунды), каждый канал также
ретраится внутри одного запуска: `FETCH_RETRIES` (по умолчанию 3) попыток с
интервалом `FETCH_RETRY_DELAY_MS` (по умолчанию 15000). Увеличьте число
ретраев, если ваша сеть теряет t.me на более долгие промежутки.

### Окно свежести

В пайплайн попадает только свежая информация: первый запуск собирает не более
24 часов назад, далее — ровно интервал между выпусками (для следующего выпуска
нужно только то, что изменилось с предыдущего). Окно применяется на каждом
этапе: `fetch` отбрасывает сообщения превью старше окна, `process`
кластеризует только НОВЫЕ посты внутри него, а `generateEdition` размещает
лишь истории, чей первый пост попал в окно.

### Персонализация (подборка источников)

Любой читатель может добавлять свои публичные каналы и управлять тем, сколько
какого источника попадает в его личный дайджест:

- **Настройки → «Источники»:** у каждого источника есть выключатель и вес 1–10
  («сколько информации откуда»). Канал добавляется по имени прямо там.
- Добавление канала создаёт глобальный источник (его забирает worker) и
  автоматически подписывает добавившего пользователя с весом 8; владелец (или
  админ) может его удалить.
- **«Моя газета»** ранжирует статьи по наибольшему весу источника истории,
  скрывает статьи из отключённых источников и применяет ограничение по объёму.

Данные: `Channel.ownerUserId` (кто добавил источник) + `ChannelSubscription`
(пользователь × канал, `weight` 1–10, `enabled`).

### Редакционный пайплайн

```
raw posts ─► normalize ─► spam ─► cluster ─► classify ─► importance ─► write ─► stories
                                                              │
                             edition (движок вёрстки) ◄────────┘
```

Истории размещаются в выпуск функцией `buildEditionLayout`: первая полоса с
одной главной историей и до четырёх коротких анонсов, далее рубрики в
каноническом порядке (мир, европа, россия, технологии, наука, бизнес, игры,
спорт, культура), не более трёх историй на страницу, в конце — рубрика
«Лёгкое чтение» для забавных историй. Все рубрики проходят через опциональный
AI-слой (Ollama) или детерминированные правила.

Заголовки — всегда сжатая фраза, а не дословная копия статьи (слабые глаголы
вроде «произошло» удаляются, предложение-содержание выбирается по ключевым
словам). Каждая статья заканчивается источником и **временем публикации
новости** («Опубликовано: 14 августа 2026, 14:31»).

Самореклама каналов вырезается из постов до попадания в пайплайн
(«подписывайтесь на наш канал в MAX», «больше новостей — на нашем канале»,
брендированное «Читайте нас в MAX» и т.п.) — `TelegramPost.raw` сохраняет
исходный текст. Также удаляются неподдерживаемые символы (вариационные
селекторы, скин-тоны, флаги, keycaps), а из заголовков — эмодзи, ссылки и
мусорная пунктуация.

Истории с реальным фото из Telegram получают изображение в статье (только
основные статьи, никогда — короткие анонсы); фото отдаются локально через
`/api/media`. Текст статьи поддерживает `**жирный**`, `*курсив*` и ссылки,
закрывающая строка «Опубликовано: …» оформляется как подпись.

Переворот страницы — реалистичный «лист бумаги» вокруг корешка (с обратной
стороной страницы и глубиной), на мобильных — сворачивание одиночной страницы.
При `prefers-reduced-motion` анимация заменяется мгновенной сменой страницы.

## Быстрый старт (локальная разработка)

**Один клик:** дважды кликните `start.bat` (Windows). Он поднимет Postgres в
Docker, применит миграции, засеет демо-данные, сгенерирует выпуск за сегодня,
запустит web + worker в двух окнах и откроет браузер. `start.bat fresh` также
сбрасывает базу данных.

```bash
# 1. Настроить окружение
cp .env.example .env          # заполнить DATABASE_URL, SESSION_SECRET, ADMIN_EMAILS…

# 2. Запустить PostgreSQL
docker compose up -d db

# 3. Установить зависимости и подготовить базу
npm install
npm -w @fun/db run db:deploy   # применить миграции
npm run db:seed:demo           # категории + реальные публичные Telegram-каналы + админ

# 4. Собрать реальные новости и выпустить сегодняшний номер (нужен доступ к t.me)
npm run pipeline:run           # fetch → process → edition

# 4б. …или запустить один шаг пайплайна по требованию (планировщик не нужен)
npm run pipeline:run fetch    # только сбор
npm run pipeline:run process  # только кластеризация/истории
npm run pipeline:run edition  # только вёрстка сегодняшнего номера

# 5. Запустить приложения
npm run dev:web                # http://localhost:3000
npm run dev:worker             # плановые задачи (fetch/process/editions/cleanup)
```

Вход по засеянному демо-админу: **`demo@fun.app` / `demo1234`** (только для
локального демо).

## CI

`.github/workflows/ci.yml` прогоняет typecheck, lint, юнит-тесты и e2e-набор
Playwright (против сервис-контейнера Postgres) на каждый push/PR.

## Сквозные тесты

Набор Playwright автоматически готовит **свежую** базу: сбрасывает схему,
применяет миграции, сеет демо-данные, запускает job'ы process + edition,
поднимает dev-сервер Next.js и гоняет тесты в установленном Edge/Chrome.

```bash
npm run e2e
```

Покрытие: регистрация/вход/выход, ошибки неверного пароля, просмотр газеты
(оглавление, модалка статьи, переворот страницы), архив, полнотекстовый поиск,
сохранение настроек, «Моя газета» и админ-панель с ролевой защитой.

## Docker compose (полный стек)

```bash
# База + web + worker
docker compose up -d --build

# …с локальной LLM для доработки текстов ИИ
docker compose --profile ai up -d --build
```

Compose-файл переопределяет `DATABASE_URL` на хост-имя сервиса `db`, поэтому
контейнеры обращаются к PostgreSQL без предположений о localhost. Профиль `ai`
запускает Ollama на порту 11434.

## Модель данных (главное)

`Channel` → `TelegramPost` (raw JSON хранится неизменным) → `StoryPost` →
`Story` → `Article` → `ArticleSource` (прослеживаемые ссылки t.me) → `Edition`.
`UserPreference` персонализирует язык, рубрику юмора и объём контента.
`ProcessingJob` фиксирует каждый запуск пайплайна для админ-панели.

Демо-доступы существуют только для офлайн-оценки (`demo@fun.app` / `demo1234`).
Сид сознательно не содержит **никаких заглушек-новостей**: в нём только
реальные публичные каналы (bbbreaking, rbc_news, readovkanews, tjournal,
nplus1, sportexpress, kinopoisk, mash, banksta), а газета собирается из живых
постов Telegram через `npm run pipeline:run`. Ограничение частоты входа
(`AUTH_RATE_LIMIT`, по умолчанию 20 за 15 мин) поднято до 200 в локальном
`.env`, чтобы разработка и e2e не упирались в него. Сырой текст Telegram
хранится дословно и никогда не переписывается; сгенерированные тексты статей
явно производны от источников, показанных в каждой статье.
